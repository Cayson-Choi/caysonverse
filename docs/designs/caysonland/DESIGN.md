# 케이슨랜드 (Caysonland) 설계서 — 1단계

작성 2026-11-17 · 브랜치 `feat/caysonland` · 1단계 = 설계 + 놀이기구 1개(별똥별 급행, 롤러코스터)를 끝까지 동작시키기.

## 0. 주인님 말씀과 원칙

- "케이슨랜드 놀이기구는 에버랜드처럼 만들도록 하고" / "케이슨랜드도 실제와 같이 만들어서 놀이기구에서 1인칭 뷰를 했을 때 실제 놀이기구 타는 느낌이 나도록 만들어야 해."
- **놀이기구는 전부 우리 것(오리지널)**: 에버랜드와 같은 규모·품질·종류(코스터, 회전목마, 관람차, 흔들배, 자유낙하, 찻잔)이지만 실제 공원의 기구 모양·이름·상표·그림은 베끼지 않는다. 이름·장식·색은 케이슨 브랜드(크림 #F3EFEA, 인디고 #4B4FD8, 바이올렛 #8B5CF6, 별 금색).
- 미술 규칙: 유럽 동화 느낌, 실사 텍스처 + 볼륨과 디테일, 전부 새것·말끔, 밋밋하거나 싸 보이지 않게. 끊김 없음(한 방 30명, 동시 접속 100명이 부드럽게).
- 하지 않는 것: 푸시, 병합, 배포(1단계 범위 밖). 비밀 출력 금지.

## 2. 좌석 번호 예약 (append-only)

- main 마지막 사용 번호 269. lots2(`feat/lots2-wiring`)의 학교·예배당·도서관·절·교회·정문 좌석이 그 뒤를 잇는다. 그 범위는 이 가지에서 건드리지 않는다.
- **케이슨랜드는 400부터** 쓴다.
  - 400–449: 정문 광장·별빛 광장 벤치, 대기줄 벤치
  - 450–499: 식당·간식 가게 의자
  - 500–599: 예비(2단계 이후 구역)
- 번호는 **한 번 정하면 바꾸지 않고 추가만** 한다(서버가 `Player.seatIndex`를 int16으로 보내므로 400대도 안전).
- 놀이기구 좌석은 이 표와 **별개**: `Player.rideSeat`(int8, 0..) 와 기구 번호(아래 §5). 그래서 기구를 늘려도 걷는 자리 번호가 밀리지 않는다.

## 3. 공원 배치와 들어가는 길

정문(`lot_gate`) → "케이슨랜드 입장" 문 → `UseDoor`와 같은 흐름으로 `area = "park"`. 마을은 이 동안 마운트하지 않는다(추모관과 같음). 공원 안에는 마을 모델 대신 `park.glb`(구역별로 쪼갠 파일, 구역은 가까이 오면 지연 로드)가 선다. 한 방 30명 그대로이므로 공원 안 사람은 30명 이하.

```
                         [ 정문 광장 ]  ← 마을에서 들어오는 곳 (입장 문, 기념품·안내)
                              │
   ┌──────── 별빛 광장 (중앙, 분수 + 달 조형) ────────┐
   │   달빛 회전목마          하늘 등불 바퀴            │
   │                                                   │
 달토끼 숲                                      별똥별 계곡
 (토끼 찻잔, 달배)                        (별똥별 급행 코스터, 구름 낙하탑)
```

- 걷는 길은 지금 마을과 같은 규칙(클릭 이동, 충돌 격자). 동선은 중앙 광장을 지나 각 구역으로. 구역 사이 거리 ≤ 90 m.
- **기구 6개 (모두 오리지널)**

| 기구 | 종류 | 구역 | 좌석 | 운행 |
| --- | --- | --- | --- | --- |
| 별똥별 급행 | 강철 롤러코스터(66 m 체인 리프트, 80° 낙하, 낙타등, 높은 회전, 뒷부분: 다이브·수직 루프·제로G 롤·토끼 언덕 3개·540° 헬릭스·터널) | 별똥별 계곡 | 12 | 136초 주기 (구현됨, §6) |
| 달빛 회전목마 | 3줄 회전목마, 말은 위아래로 흐른다 | 별빛 광장 | 24 | 2.5분, 가속→정속→감속 |
| 하늘 등불 바퀴 | 높이 38 m 관람차, 곤돌라 12개 | 별빛 광장 | 48 | 한 바퀴 4분 |
| 달배 | 양쪽으로 흔들리는 큰 배 (최대 55°) | 달토끼 숲 | 32 | 1.5분, 흔들림이 점점 커짐 |
| 구름 낙하탑 | 42 m 자유낙하 탑, 네 면 | 별똥별 계곡 | 16 | 1분: 천천히 오름 → 정지 → 자유낙하 → 제동 |
| 토끼 찻잔 | 판이 돌고, 컵이 따로 돌고, 컵 안 핸들로 더 돌린다 | 달토끼 숲 | 24(컵 6개×4) | 2분 (컵 돌림은 라이더 입력) |

## 4. 한 기구의 공통 모델

모든 기구는 같은 모양이다. 새 기구를 만드는 일은 "기구 정의 + 시간표 함수 + 모델 + 카메라 설정"을 채우는 일이다.

```
RideDef = { id, seats, cycleMs, dwell{unloadMs, boardMs, gateMs}, at(nowMs) → 기구 상태, seatFrame(state, seat) → 위치·방향 }
```

- **시간표**: `at(nowMs)`는 순수 함수. 서버와 모든 클라이언트가 같은 값을 계산한다. 위치를 보내지 않는다 → 네트워크는 "누가 어느 자리"만. 100명이 같이 봐도 서버 일은 같다.
- **탑승**: 대기줄 끝 "탑승 문"에서 `RideBoard{ride}` → 서버가 자리를 정한다(가장 낮은 빈 자리). 열려 있을 때만(내리는 시간 뒤 ~ 출발 6초 전). 닫힘·만석·앉아 있음은 `RideNotice`로 이유를 알려 준다.
- **하차**: 서버가 다음 주기의 하차 시간에 모두 내려 준다(서버가 정한다). 중간에 "비상 내리기"는 항상 있다(§7).
- **구경하는 사람**: `Player.rideSeat`가 ≥ 0이면 `RemotePlayer`가 그 사람을 시계가 말해 주는 좌석 자리에 앉혀서 그린다(차가 기울면 같이 기운다).
- 기구가 여러 개가 되면 `Player.rideId`(uint8)를 추가한다(지금은 코스터 하나라 `rideSeat`만; 스키마는 끝에 추가만 하는 규칙).

## 5. 멀티플레이 규칙 (서버: `server/src/rooms/villageCoaster.ts`)

1. `RideBoard`: 열린 구간(`unloading` 뒤 ~ `gate` 전)만. 앉아 있거나 버스·낚시 중이면 `busy`. 12석이 차면 `full`.
2. 좌석은 서버가 준다(`Player.rideSeat`). 클라이언트는 자리를 고르지 못한다 → 자리 싸움·부정 없음.
3. 하차: `tick`(0.5초)이 "탄 주기"가 끝난 사람을 다음 주기 하차 시간에 내려 준다. 연결이 끊기면 즉시 비운다.
4. 거리 규칙: park area에서 코스터 대기줄 패드 9.2 m 안(2단계 구현).
5. 한 방 30명이라 한 기구에 같이 탈 수 있는 수는 좌석 수(코스터 12)가 위다.

## 6. 1인칭 카메라 (구현됨: `client/src/land/coasterRide.ts`)

"실제로 타는 느낌"은 다음에서 나온다. 숫자는 코드 상수이고 `comfort` 설정(끔 / 약하게 / 실감나게)으로 한꺼번에 줄인다.

| 요소 | 어떻게 | 실감의 이유 |
| --- | --- | --- |
| 눈 위치 | 좌석 방석 위 0.92 m, 좌우 ±0.42 m, 차 틀에 붙음 | 앞 레일·보닛·안전바가 보이고 수평선이 선로를 따라 기울고 뒤집힘 |
| 차 회전 지연 | 차의 방향이 카메라에 감쇠 스프링(~60 ms)을 거쳐 닿음 | 급한 기울기 변화가 머리 관성처럼 조금 늦게 옴 |
| 머리 흔들림 | G(세로 −1.2..4.5, 가로, 앞뒤)가 머리를 미는 스프링: 최대 몇 cm·몇 도 (세로 G 클수록 아래로, 무중력엔 위로, 커브 바깥으로 기울고, 출발 때 뒤로 젖음) | 풀아웃·루프에서 눌리고 낙타등에서 뜨는 느낌 |
| FOV | 속도(최대 +5°)와 내리막(+5°)에 따라 렌즈가 열림 | 속도감 |
| 진동 | 속도에 비례한 잔떨림(0.4°, 1 cm) | 레일 이음새 |
| 둘러보기 | 화면 끌기(PC·폰). 좌우 ±110°, 위아래 ±70° | 자유롭게 보되 몸은 차에 붙음 |
| 소리 훅 | `coasterAudio.ts`(WebAudio 합성): 바람(속도 제곱), 레일 웅웅, 체인 리프트 딸깍 (초당 4회, 3.4 m/s), 낙하 | 파일 없이 용량 0. 소리 끄기 버튼 |

물리(`shared/src/land/coaster.ts`): 체인 4.0 m/s, 자유 구르기에 구름·공기 손실 1.2%, 제동 4.2 m/s², 높은 회전 뒤 블록 브레이크 13.5 m/s.
2026-11-19 개편(주인: "아주 높이 올라가게", "뒷 부분은 그냥 밋밋해"): 리프트 45°로 레일 높이 67.8 m(승강장 위 66 m), 80° 낙하, 낙타등(에어타임), 높이 30 m의 경사 회전, 블록 브레이크, 그리고 뒷부분에 다이브·수직 루프(29 m)·제로G 롤(심장선 회전)·토끼 언덕 3개·540° 지상 헬릭스(위 바퀴가 아래 바퀴와 브레이크 길 위를 지남)·터널. 세로 곡선은 힘으로 모양을 잡는다(곡률 = A·모양(u)·g/v²): 빠른 곳은 완만하고 느린 곳은 촘촘하다. 경사(뱅크)는 탑승자 심장선(레일 위 1.1 m)을 축으로 돌려 옆으로 흔들리지 않는다. 지지대는 `shared/src/land/coasterSupports.ts`가 놓고 검사한다(격자 탑, 뒤집힌 곳·헬릭스는 옆 기둥+팔).
측정(테스트로 고정): 최고 속도 35.8 m/s(약 129 km/h), 심장선 세로 G 최대 4.33 / 최소 −0.75, 가로 G ≤ 0.4, 총길이 ~1316 m, 주행 94.4 s, 0.5 m마다 G 변화 ≤ 0.35, 곡률 변화 ≤ 0.01/m (`coaster.test.ts`).

## 7. 안전·편안함

- 모든 화면에 **내리기 버튼**이 항상 있다(달리는 중엔 "비상 내리기"). 서버가 즉시 좌석을 비우고, 카메라는 같은 프레임에 마을 카메라로 돌아온다.
- **움직임 설정**: 끔(머리 흔들림·FOV·진동 없음, 차의 기울기만 낮게), 약하게(절반), 실감나게. 기기에 저장(`localStorage`), 없어도 동작.
- 루프 위 뒤집힘이 있는 기구는 탑승 전 안내판에 "뒤집혀요"를 적는다. 폰에서도 48 px 버튼 규칙.
- 가로 G ≤ 1.4, 세로 G −0.5..4.5(테스트로 고정). 안전 문턱을 넘으면 설계를 고치게 하는 테스트다.

| 텍스처 | 기구 하나 ≤ 3장(1K) | 2장(집 공용 소나무·돌, 폰은 절반 크기) + 캔버스 간판 1 + 잔디 1 |
| 상시 비용 | 서버 계산 0 | 열차 6칸 행렬 갱신 + 카메라 스프링: 프레임당 < 0.1 ms. 서버는 0.5초 간격 하차 검사뿐 |
| 새 재질 | 첫 사용 컴파일은 `ProgramGate`가 흡수 | 공원 입장 막 뒤에서 웜업 목록(2단계) |

- 부분 로드: 기구 모델은 구역 단위 파일, 가까이 오기 전엔 안 불러온다.
- LOD: 버팀대·침목은 멀면 청크째 컬링. 폰은 침목·버팀대 사다리 줄이기 가능(청크 단위 스위치).
- 열차 인스턴싱: 칸 6개를 1호출. 좌석 사람 6~12명은 일반 아바타 예산 안.
- 측정 한계: 헤드리스 Chrome(vsync 60 fps 상한)이라 "남는 여유"는 보이지 않는다. 2단계에서 100명 부하(`loadtest`)와 느린 폰 한 대로 다시 잰다.

## 9. 공원 area와 정문 (2단계, 구현됨)

- `Player.area === "park"`(`shared/village/parkArea.ts`). 마을 정문 문 패드(`lot_gate`의 `lot_gate_main`)에서 "케이슨랜드 들어가기"(E / 폰은 동그란 버튼) → 검은 막(`DoorFade`) → 서버 `UseDoor`(`useParkDoor`)가 공원 도착 지점으로 옮기고 area를 바꾼다. 공원 안 아치 아래 패드에서 "케이슨랜드 나가기"로 돌아온다.
- 공원은 **자기 좌표계**(코스터 트랙 로컬 미터: 승강장이 원점, z는 남쪽). 마을과 겹쳐도 area 필터 때문에 서로 안 보인다. 서버는 `geometryFor(player)`로 공원 전용 충돌(`parkGeometry`: 경계 + 상점·큐 홀·승강장·분수·나무)을 쓴다. 클라이언트는 `PARK_ACTIVE_MAP`.
- 공원 지도: 정문 아치(z -186) → 산책로(상점 6채) → 별빛 광장(분수, z -112) → 서쪽으로 코스터 대기줄(탑승 패드 (-17,-46)), 동쪽 대로는 다음 기구 자리(회전목마 (110,-135), 관람차 (205,-135))를 비워 둠. 코스터 회로는 z ≥ 0으로 공원 남쪽 끝(z -2.2)에서 막는다.
- 탑승: 대기줄 입구 패드 근처에서 "별똥별 급행 타기"(E). 서버는 area가 park이고 패드에서 9.2 m 안일 때만 허락한다(`villageCoaster.canBoard`).
- 시험 입구(`?land=coaster`)는 없앴다. e2e(`e2e/coaster-ride.mjs`)는 마을에서 정문 문으로 들어가 대기줄까지 걸어가서 탄다.
- 아직 없는 것: 공원 입장 막 뒤의 로딩 표시(지금은 막이 걷히며 공원이 바로 선다), 밤 하늘·조명(하늘은 낮 그라디언트), 공원 안 앉을 자리(400번대 좌석 예약만).

## 10. 텍스처와 미술

- 실사 CC0: ambientCG `Grass001`(잔디), `PavingStones070`(포장), `Gravel023`(샛길), `PaintedMetal013`(도장 강관의 표면·광택), `RoofingTiles013A`(지붕), `Concrete034`(기초). 1K WebP로 `client/public/textures/park/`, 라이선스 기록은 같은 폴더 `LICENSE.md`(주인님 허락 2026-11-17). 집 공용 소나무·회반죽(`textures/houses`)도 쓴다. 폰용 절반 크기·KTX2 변환은 남았다.
- 구조물은 Blender 스크립트로 만든 GLB(구역별), 코스터는 코드로 생성(트랙 곡선이 데이터)이라 GLB가 필요 없다.
- 실제 놀이기구 참고(오리지널 보장): 구조 비율·지지대 간격·안전바·체인 리프트 같은 "실제 구조 상식"만 참고하고, 어떤 공원의 기구도 모양을 따라 그리지 않는다.

## 11. 만드는 순서

1단계 (이번, 끝남): 설계서, 별똥별 급행(트랙·물리·시간표·서버 좌석·원격 라이더·1인칭 카메라·HUD·소리), 시험 입구, e2e.

2단계 (다음):
1. 공원 area(`park`) + 정문 문·`DoorFade`·입장 지점 + 걷는 지도(충돌 격자)·길찾기, 기구 문의 거리 검사. 공원 area 안에서는 `VillageDoors`의 마을 항목을 끈다.
2. 별빛 광장(분수·달 조형·벤치 400번대 좌석) + 동화 풍경(박공 가게 거리) + 실사 텍스처 교체.
3. 별똥별 급행 미술 마감: 승강장 대기줄(대기 줄이 늘어서 보이는 연출), 안전 게이트 열림/닫힘, 열차에 별 문양·번호판, 레일 이음 소리, 낙하 때 보이는 풍경.
4. 달빛 회전목마(가장 쉬움: 회전 + 위아래), 하늘 등불 바퀴(곤돌라는 중력으로 수평).
5. 달배, 구름 낙하탑, 토끼 찻잔(라이더 입력 동기화).
6. 공원 부하 시험(30명 한 방, 100명 합), 폰 성능, 밤 조명(등불·불꽃놀이).

## 12. 열린 질문 (2단계 전에 주인님 확인)

- 실사 CC0 텍스처 내려받기 허락(§10).
- 입장료·정기권은 취소된 경제 계획과 연결하지 않는다(입장은 무료로 둔다).

## 13. 1단계에서 발견한 기존 버그 (같이 고침)

`RemotePlayer`가 아바타 그룹의 자동 행렬 갱신을 끄고(`matrixWorldAutoUpdate = false`, 먼 아바타를 몇 프레임에 한 번만 갱신하는 성능 커밋 9fc5ac4) `group.updateMatrixWorld(true)`만 불렀다. three 0.185는 이 깃발이 꺼진 그룹의 **자기 matrixWorld를 갱신하지 않으므로**, 서 있는 원격 플레이어가 월드 원점(마을에서는 분수 한가운데)에 그려졌다(이름표만 분수 위에 떠 있음). `refreshAvatarMatrices`(부모 행렬 × 로컬 행렬을 직접 계산)로 고쳤다. 원격 라이더 검증이 이 문제를 드러냈다. main에도 있는 문제이므로 별도로 배포 판단이 필요하다.

- 근거: 점검 보고서 `../audit/audit.md`, 레퍼런스 조사 `../research/refs.md`.
- 시안 그림: `overview.jpg` (새 디자인 3장 + 평면도 + 지금 화면 3장). 원본 렌더는 `work/render_*.png`, Blender 시안 파일은 `work/mockup.blend`, 만든 스크립트는 `work/mockup.py` 예요.
- 시안은 **배치와 분위기를 보여 주는 Blender 블록 시안**이에요. 실제 빌드는 지금 파이프라인(텍스처, 라이트맵 굽기)으로 버스·집 수준의 질감과 디테일을 입혀요. 사람 모양은 크기 비교용 임시 모형이에요(머리 꼭대기 2.16 m).

## 0. 한눈에

**왜 다시 만드나요?**
- 지금 추모관은 옛 9×12 m 방을 늘린 모델이에요. 그래서 가구가 찌그러져 있고, 소품·충돌 상자·앉는 자리가 화면과 어긋나 있어요.
- 소파는 원래 앉는 자리로 등록된 적이 없어요. 소파 옆에 뜨는 "앉기"는 집 안 자리가 새어 나온 가짜예요.

**무엇을 바꾸나요?**
1. **모습:** B안 건물(안쪽 15×12 m, 천장 4.5 m)을 처음부터 새로 지어요. 늘이기는 하지 않아요.
   - 북쪽 벽에는 흰 봉안함 A·B를 두고, 그 사이 가운데에 아치형 "기억의 자리"(추모 니치와 천창)를 둬요.
   - 동쪽 벽은 원목 유리문 봉안함이에요.
   - 서남쪽은 가족 라운지예요. ㄱ자 소파, 라운지 의자, 티 코너, 정원 창이 있어요.
   - 동남쪽은 안내 데스크예요. 브랜드 벽과 이름 찾기 키오스크가 있어요.
   - 가운데에는 벤치를 두고, 문에서 니치까지 통로를 내요.
2. **앉기:** 추모관 안의 소파·의자·벤치 **22자리 전부**에 앉을 수 있게 해요. 앞마당 벤치 4자리도 앉을 수 있어요.
   - 소파와 라운지 의자에서는 몸을 뒤로 기대는 "소파 자세"로 앉아요.
   - 의자와 벤치에서는 지금의 "의자 자세"로 앉아요.
   - 앉을 수 있는 가구는 빌드할 때 자동 검사로 빠짐없이 확인해요. 앉는 자리 없는 의자는 빌드가 실패해요.
3. **동작:** 이렇게 이어져요.
   - 들어오기 → 안내원 인사 → 이름으로 찾기 → 칸 가까이 보기
   - 꽃 놓기·LED 초·편지 → 빈 칸에 **우리 아이 모시기**(사진과 이름)
   - 기억의 자리에서 추모하기 → 라운지에서 쉬기 → 나가기
   - 1단계는 무료예요. 2단계 결제를 붙일 자리는 지금부터 데이터 구조에 만들어 둬요.
4. **기간(정직한 추정):** 1단계까지 **약 18.5 작업일(여유를 두면 20~22일)**이에요. 결제(2단계)는 따로예요(5장).

**먼저 결정해 주실 것** (6장에 자세히)
- 가짜 예시 칸(지금 218칸)을 출시 때 어떻게 할지
- 무료 베타로 모신 칸을 2단계에서 어떻게 대우할지
- 사진을 공개하기 전에 검토할지
- 칸 수(368칸 안)

천장
- 평평한 흰 천장에 둘레 간접조명(코브)을 둬요.
- 니치 위에 2 × 2.7 m 천창을 내요.
- 라운지 위에는 원목 루버를 달아요.
- 다운라이트 10개를 둬요.
- 카메라는 지금처럼 천장 아래에 머물러서 천장이 보여요.

### 1-2. 재료
- 바닥: 밝은 오크 마루(폭 18 cm 판)
- 벽: 따뜻한 흰 회벽, 걸레받이는 오크
- 포인트 벽: 세이지 그린(브랜드 벽, 라운지)
- 금속: 금색(명패, 글자, 손잡이)과 샴페인 알루미늄(문, 창)
- 패브릭: 웜 그레이 소파, 크림색 라운지 의자, 세이지·테라코타 쿠션
- 칸 안: 흰 래커(A·B), 자작 하우징, 도자기 유골함
- 색은 칸 안의 꽃과 사진이 내요(refs 0장 1번).

### 1-3. 칸 하나의 모습 (봉안함 디테일)
- 기본 세트는 이렇게 들어가요.
  - 집 모양 자작 하우징(박공지붕)과 앞면 금색 명패(이름)
  - 기대 세운 사진 액자(가족이 올린 사진)
  - 작은 꽃병과 조화
  - LED 초
  - 칸 앞턱의 이름 카드
- 꾸미기는 칸마다 달라요(2단계 상품 후보): 지붕 색, 유골함 종류(흰 도자기, 분홍, 민트, 월넛, 금색), 꽃, 장난감, 간식, 액자 테두리.
- 빈 칸에 다가가면 보라색 테두리와 "+ 우리 아이 모시기" 판이 떠요(시안 ② 사진).
- 모든 소품의 바닥 높이는 칸 바닥에 정확히 맞춰요. 지금처럼 25 cm 떠 있으면 안 돼요. 빌드 검사로 ±1 cm 안에 있는지 확인해요.

### 1-4. 낮과 밤 조명
| | 낮 (06~18시) | 밤 (18~06시) |
|---|---|---|
| 창밖 | 햇살 정원, 서쪽 창으로 햇빛 줄무늬 | 어두운 정원, 정원등과 별 (지금은 밤에도 한낮 그림인 문제를 고쳐요) |
| 천창 | 하늘빛 빛기둥이 니치를 비춤 | 짙은 남색, 니치의 따뜻한 조명만 |
| 실내 | 코브 100%, 다운라이트, 밝고 차분함 | 코브 60%, 다운라이트는 줄이고 칸 줄조명과 LED 초가 주인공. 더 따뜻하고 조용함 |
| 구현 | 라이트맵 2장(낮/밤)을 구워서 마을의 `dayNightBlend`/`nightLightmap` 방식으로 섞어요 | 같음 |

### 1-5. 소리
- 추모관에서는 마을 배경음악을 끄고 전용 배경을 틀어요: 잔잔한 피아노·오르골 루프와 아주 작은 실내 공기 소리.
- 효과음: 나무 바닥 발소리, 자동문 소리, 들어올 때 작은 차임, 촛불 켜는 "딸깍", 꽃 놓는 바스락, 편지를 우체통에 넣는 소리.

### 1-6. 지금 추모관에서 살리는 것
- 건물 바깥 모양(나무 루버와 유리 정면), B안 치수, 문 발판·도착 자리
- 카메라 규칙(천장 아래 머물기, 벽 밀어내기)
- 안내원 대화(질문 4개, AI 음성)
- 촛불을 방 안 모두에게 보이게 하는 서버 흐름
- 칸 카드 화면의 틀
- 소품 인스턴싱 방식과 사진 아틀라스 방식

## 2. 동작 — 방문객 여정

PC는 지금처럼 WASD/클릭 이동, E 상호작용, 마우스 궤도 카메라예요. 폰은 조이스틱과 큰 버튼이에요.

| 단계 | 무엇이 일어나나 | PC 카메라·UI | 폰 카메라·UI |
|---|---|---|---|
| 1. 다가가기 | 앞마당 돌벤치(등받이 있는 새 모델 2개), 금색 글자. 2.5 m 안에 들어오면 자동문이 스르르 열려요(지금 autoDoor 로직, 모델 문짝) | 평소 3인칭 | 같음 |
| 2. 들어가기 | 열린 문턱을 **걸어서 지나가면** 화면이 살짝 어두워졌다 밝아지며(DoorFade) 안으로 들어가요. "E 들어가기"는 보조로 남겨요 | 안에서 북쪽(니치)을 보며 시작해요 | 시작 카메라를 머리 뒤 5.5 m, 높이 2.8 m로 해요(지금 너무 붙는 문제 해결) |
| 3. 인사 | 처음 온 사람에게 안내원이 말풍선으로 인사해요: "어서 오세요. 찾으시는 아이가 있나요?" 버튼은 [이름으로 찾기] [둘러볼게요] [우리 아이 모시기] | 말풍선 + 버튼 3개 | 아래쪽 시트로 보여요 |
| 4. 찾기 | 키오스크·안내원·윗줄 "찾기" 버튼 어디서든 이름(반려동물 이름이나 가족 별명)으로 찾아요. 결과에는 사진, 이름, "A구역 4단 8번"이 나와요. 하나를 고르면 바닥에 은은한 빛 길이 생기고 그 칸이 빛나요. [바로 가기]를 누르면 자동으로 걸어가요(방 안 길찾기 격자) | 오른쪽 패널 | 전체 화면 시트, 검색창은 자판 위로 |
| 5. 가까이 보기 | 칸 벽 1.5 m 안에서 **마우스·화면 가운데에 있는 칸 하나**가 테두리로 강조돼요(지금은 열 단위라 어느 칸인지 안 보여요). E나 탭을 누르면 카메라가 그 칸 앞 1.0 m, 칸 높이로 부드럽게 다가가요. 다른 사람이 카메라 앞 1.2 m 안에 있으면 반투명이 돼요 | 오른쪽 카드: 사진(크게), 이름, 날짜, 한 줄, 받은 꽃·초·편지 수. 버튼: 꽃 놓기 / LED 초 켜기 / 편지 남기기 / 앨범. ←→↑↓로 옆 칸 | 아래 45% 시트. 위쪽 55%에 칸이 보여요. 좌우로 밀어서 옆 칸 |
| 6. 꽃 놓기 | 헌화 꽃대에서 꽃을 집으면 아바타가 들고 다녀요(1단계 무료). 칸에서 [꽃 놓기]를 누르면 그 칸 앞턱에 꽃이 놓이고 24시간 모두에게 보여요. 한 칸에 최대 5다발, 오래된 것부터 사라져요 | 들고 있는 꽃 아이콘 | 같음 |
| 7. LED 초 | [LED 초 켜기]를 누르면 칸 안 초가 10분 동안 깜빡이며 켜져요. 방 안 모두에게 보이고 "○○님이 초를 켰어요"가 떠요(지금 기능을 이어 씀) | — | — |
| 8. 편지 | 편지 테이블에 앉거나 카드의 [편지 남기기]로 200자까지 써요. [하늘 우체통]에 넣으면 그 칸 안에 작은 봉투가 생겨요. 공개 / 가족만 고를 수 있어요. 욕설 필터와 신고 기능이 있어요 | 편지지 모양 창 | 전체 화면 편지지 |

### 2-1. 여럿이 함께 있을 때(예절)
- 같은 칸을 여러 사람이 동시에 볼 수 있어요. 잠그지 않아요. 카드에 "○○님도 함께 보고 있어요"가 작게 떠요.
- 꽃·초·편지 봉투는 모두에게 보여요. 사진·이름은 칸 주인이 "가족만 보기"를 고르면 다른 사람에게는 이름만 보여요(2단계 옵션 후보).
- 추모관 안에서는 이렇게 해요.
  - 달리기는 걷기 속도로 줄여요.
  - 큰 감정표현은 막고 3가지만 써요: 고개 숙이기, 손 모으기, 토닥이기.
  - 말풍선은 작고 옅게 보여요.
- 추모하기 중인 니치 앞 2 m는 다른 사람이 지나갈 수 있어요. 대신 그 사람의 말풍선은 숨겨요.
- 앉은 자리는 먼저 앉은 사람 것이에요. 차 있는 자리에는 "앉기"가 뜨지 않아요.
- 신고: 카드와 편지에 [신고]가 있어요. 신고 3건이면 숨기고 검토해요.

- 아바타는 앉으면 팔 폭이 약 1.05 m라서 자리 간격은 1.15 m 이상으로 해요. 그래서 3.4 m 소파에는 3명이 앉아요.
- 가구 크기는 아바타에 맞춰 실제보다 약간 크게 잡았어요(소파 깊이 0.95 m). 마을 건물을 키운 원칙과 같아요.

### 3-2. 자세
- **의자 자세:** 지금 있는 `Sit_Chair_Down / Idle / StandUp`을 그대로 써요. 발은 바닥에 안 닿고 달랑거려요. 아이 같은 비율이라 자연스러워요.
- **소파 자세(새로 만듦):**
  - `Sit_Sofa_Idle`: 상체를 12~15° 뒤로 기대고, 손은 무릎이나 팔걸이에 둬요. 쿠션에 3 cm 파묻히게 해요.
  - 앉기와 일어서기는 의자 클립을 재사용하고 마지막 0.3초만 섞어요.
  - character.glb 내보내기 규칙(포즈를 먼저 설정)을 지켜요.
- 앉는 높이는 모델에서 레이캐스트로 잰 좌면 높이를 써요. 지금 벤치처럼 15 cm 묻히는 일이 없게 빌드 검사로 ±1 cm를 확인해요.

### 3-3. 다가가기와 일어나기
- 자리마다 **다가가기 구역**(가구 둘레 0.9 m 띠)이 있어요. 그 안에 있으면 가장 가까운 빈자리에 "앉기"가 떠요. 클릭이나 탭으로 가구를 직접 눌러도 돼요. 그러면 길찾기로 걸어가서 앉아요.
- 일어나면 자리마다 미리 정한 **내리는 곳** 2~3개 중에서 비어 있는 첫 곳으로 내려요. 앞쪽이 막혀 있으면 옆으로 내려요. 빌드 때 모든 내리는 곳이 충돌 상자와 겹치지 않는지 검사해요.

### 3-4. 서버 검사 (지금 버그 고치기 포함)
- 자리를 **문자열 id**로 다뤄요(`hall:sofa:1`, `house_3:sofa:0`).
  - 지금은 전체 목록의 순번을 쓰는데, 집 안 자리 번호가 광장 벤치로 잘못 읽히는 버그가 있어요. 문자열 id로 바꾸면 이 버그가 사라져요.
- 클라이언트는 **지금 있는 구역의 자리만** 보여요(추모관에 집 자리가 새어 나오는 "가짜 앉기" 해결).
- 서버는 이렇게 검사해요: 같은 구역 → 다가가기 구역과의 거리 1.6 m 이하 → 비어 있음 → 겹침 그룹도 비어 있음 → 초당 1회 제한.
  - 거절하면 지금처럼 조용히 버리지 않고 짧은 안내를 보내요("이미 다른 분이 앉아 있어요").
- 연결이 끊기거나 나가면 자리를 비워요(지금 releaseSeat 유지).

## 4. 기술 계획

### 4-1. Blender 파이프라인 다시 빌드 (늘이기 금지)
1. **치수의 단일 출처:** `villageLayout.ts`의 추모관 숫자(방, 칸 벽, 니치, 가구 자리)를 tsx 스크립트로 `memorial_spec.json`에 내보내요. `build_memorial.py`는 이 파일만 읽어요. 그러면 코드와 모델이 다시 어긋날 수 없어요.
2. `build_memorial.py` 새로 쓰기
   - 벽, 천장, 천창, 코브를 만들어요.
   - 봉안함 3벽(A·B 14×8, 동쪽 18×8, 유리문)을 만들고 칸마다 `anchor__cubby_<id>`를 둬요.
   - 니치와 제단, 가구를 만들어요. 가구 이름은 `furn__<종류>__<id>`예요.
   - 자리 empty `seat__<id>`에는 kind, 자세, 겹침 그룹을 넣어요. 내리는 곳은 `exit__<seat>_<n>`, 충돌 상자는 `col__*`, 문짝은 `door__leaf_l/r`, 창밖 정원은 낮/밤 머티리얼로 만들어요.
3. `make_memorial_textures.py`: 오크 마루, 회벽, 래커, 자작, 세이지, 패브릭 2종, 금속, 정원.
4. `bake_memorial.py`
   - 라이트맵 **낮 1장과 밤 1장**을 구워요(PC 2048², 폰 1024², webp). 디노이즈해요.
   - 칸 안 소품은 굽지 않고 실시간 앰비언트와 칸 줄조명 근사로 처리해요.
5. `post_memorial.py`
   - GLB를 내보내요(meshopt/draco).
   - 앵커·자리·충돌 상자·내리는 곳을 JSON으로 뽑아서 `shared/`에 생성 파일로 넣어요.
6. **자동 검사**(빌드 실패 조건): 지금 점검에서 나온 문제를 그대로 검사로 만들어요.
   - 앵커 바닥과 칸 바닥의 차이가 1 cm를 넘음
   - 소파·의자·벤치인데 `seat__`가 없음
   - 좌면 높이 오차가 1 cm를 넘음
   - 충돌 상자와 가구 경계 차이가 3 cm를 넘음
   - 내리는 곳이 막혀 있음
   - 늘인 노드(scale≠1)가 있음

### 4-4. 칸·모시기 데이터 (업데이트해도 구매가 안전하게)
- **칸 id는 물리 위치 이름으로 고정해요:** `M1-A-r3-c07`(추모관 1, A구역, 3단, 7열).
  - 카드에는 "A구역 4단 8번"으로 보여요.
  - 한번 정한 id는 절대 다시 번호를 매기지 않아요.
  - 배치를 바꾸게 되면 `slot_moves`(옛 id → 새 id) 표로 옮겨요.
- **모심(claim)은 칸과 따로 있는 기록이에요:**
  - `claim_id`(uuid)가 사진·꾸미기·편지를 모두 가져요.
  - 칸을 옮기거나(창가 칸으로 업그레이드) 추모관을 새로 지어도 기록은 그대로예요.
- **구매는 "권리(entitlement)"로 저장해요:** 모델이나 칸 숫자를 바꾸지 않고 "이 claim은 이 칸을 2027-11-13까지 쓴다", "이 claim은 금색 유골함을 가진다" 같은 기록만 남겨요. 게임 업데이트가 구매에 영향을 줄 수 없어요.
- **저장소:**
  - 지금 서버에는 DB도 계정도 없어요(Colyseus 메모리뿐). 그래서 1단계에 다음을 붙여요.
    - Oracle 서버의 SQLite(WAL)
    - 매일 밤 백업
    - 사진 파일 저장소(디스크 또는 Object Storage, 원본과 512px, 128px)
  - 2단계에서 결제를 붙일 때 Postgres로 옮길지 다시 판단해요.
- **누가 주인인가:**
  - 1단계는 기기 키(브라우저에 만든 무작위 키, 서버에는 해시만 저장)와 선택 닉네임이에요.
  - 2단계는 카카오나 구글 로그인으로 바꾸고, 기기 키로 모신 칸을 계정으로 옮기는 화면을 둬요.
  - 기기 키를 잃으면 찾을 수 없다는 점을 모실 때 안내해요. 복구 코드 6자리도 보여 줘요.
- **사진 검토:**
  - 올린 사진은 주인에게만 바로 보여요.
  - 공개는 검토 뒤에 해요(관리 화면에서 승인). 출시 초기는 수가 적어서 사람이 직접 볼 수 있어요.

**Seats** (generated from `seat__*` empties, replaces `VILLAGE_SEATS` index addressing):
```ts
interface SeatDef { id: string; area: AreaId; kind: "bench"|"chair"|"sofa"|"armchair";
  pose: "chair"|"sofa"; x: number; z: number; yaw: number; seatY: number; frontEdge: number;
  approach: { minX: number; maxX: number; minZ: number; maxZ: number }; // reach zone
  exits: Point2[]; group?: string /* mutually exclusive seats */ }
// Player.seatId: string ("" = standing). Server: same area → dist(player, approach) <= 1.6
// → free → group free → rate 1/s; reject with SitRejected{reason}. Client lists seats of player.area only.
```
- Hall 22 seats: sofa 3+1 (corner group), armchair 2, centre benches 8 (approach both sides), east bench 2, letter chairs 4, consult chairs 2. Forecourt 4.
- New clip `Sit_Sofa_Idle` (lean back 12–15°, contact 0.03 lower); keep `SIT_ROOT_AHEAD` logic for chairs; sofas use the backrest plane instead (`root = backrest − 0.71 + 0.05`).

**Build-time asserts** (`post_memorial.py` + vitest):
- Every anchor's floor within 1 cm of its cell floor.

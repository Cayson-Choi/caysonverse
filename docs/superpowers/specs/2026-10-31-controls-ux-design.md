# 조작 · 카메라 · 이름표 UI/UX 개편 설계

- 작성일: 2026-10-31
- 상태: 초안 — 발주자 승인 대기
- 발주자 요청: "유명한 3D 게임의 모바일과 PC 조작 방법을 학습해서 최적의 UI/UX를 구현해" — 세부 결정은 설계자에게 위임
- 표기: **[발주자]** = 발주자가 정한 것, **[내 결정]** = 설계자가 정한 것(바꿀 수 있음)

## 1. 왜, 무엇을

지금 조작은 기능별로 하나씩 덧붙여 와서 버튼과 방식이 흩어져 있다.

- 고정 조이스틱(nipplejs)
- 1인칭 D-패드
- 클릭 이동
- 보기 토글
- 전체 지도

이번 개편의 목표는 **학생이 처음 들어와서 설명 없이 30초 안에 걷고, 둘러보고, 말할 수 있게 하는 것**이다. 기준은 이미 수억 명이 익숙한 3D 게임들의 공통 관례다. 특정 게임을 그대로 베끼지 않고, 여러 게임에 공통인 관례만 따른다.

**조사한 관례 (출처는 10장)**
- **휴대폰**
  - 왼쪽은 누른 자리에 생기는 조이스틱(로블록스 기본값), 오른쪽은 한 손가락 드래그로 시점 회전.
  - 두 손가락 핀치로 줌(제페토).
  - 오른쪽 아래에 점프·행동 버튼.
- **PC**
  - WASD 이동, Space 점프, 마우스 드래그 시점, 휠 줌.
  - `/` 또는 Enter로 채팅, Esc로 메뉴, Tab으로 접속자 목록.
- **터치 버튼 크기**: 최소 44pt(애플 HIG)·44 CSS px(WCAG AAA). 버튼 간격을 두고, 크기·위치 조절 옵션을 둔다(게임 접근성 가이드라인).
- **이름표**
  - 거리에 따라 크기를 제한 범위 안에서 조절하고, 멀면 서서히 사라지게 한다.
  - 벽에 가리면 흐리게 한다. 갑자기 사라지지 않고 페이드한다.

## 2. PC 조작 **[내 결정]**

| 동작 | 키·마우스 | 지금과 달라지는 점 |
|---|---|---|
| 걷기 | WASD / 방향키 | 같음 |
| 달리기 | Shift 누르는 동안 (걷기의 1.6배) | 새로 생김 — 서버 속도 검증도 같이 바꿈(5장) |
| 점프 | Space | 새로 생김 — 보이기용 깡총(5장) |
| 시점 돌리기 | 마우스 드래그(왼쪽·오른쪽 버튼 모두), Z/C 키 | 노트북 터치패드에서도 쉽게 왼쪽 드래그 허용 |
| 카메라 뒤로 정렬 | R | 새로 생김 — 캐릭터 등 뒤로 카메라를 바로 돌림 |
| 줌 | 마우스 휠 | 범위 제한, 부드럽게 |
| 걸어가기 | 바닥을 짧게 클릭 | 같음 (목적지에 표시가 생김) |
| 상호작용 | E (F도 같음) — 앉기·조교와 대화 | 앉기 `T`/대화 `T` 등 흩어진 키를 E 하나로 |
| 채팅 | Enter 또는 `/` 열기, Enter 보내기, Esc 닫기 | `/` 추가 |
| 이모지 | 숫자 1~6, 또는 화면 이모지 버튼 | 숫자키 추가 |
| 접속자 목록 | Tab 누르는 동안 | 새로 생김 |
| 지도 | M | 지금의 "전체 보기"를 지도 버튼·M으로 |
| 1인칭/3인칭 | V | 같은 기능, 키 정리 |
| 메뉴(설정) | Esc | 새로 생김 |

## 3. 휴대폰 조작 **[내 결정]**

**화면 구역(엄지가 닿는 곳 기준)**
- **왼쪽 아래 절반**: 아무 데나 엄지를 대면 그 자리에 조이스틱이 생긴다(다이내믹 조이스틱).
  - 살짝 밀면 걷기, 끝까지 밀면 달리기.
  - 손을 떼면 사라진다.
  - 화면 왼쪽 가장자리 24px 안쪽은 시스템 뒤로 가기 제스처와 겹치므로 반응하지 않는다.
- **오른쪽 절반**: 한 손가락 드래그는 시점 회전, 두 손가락 핀치는 줌.
- **오른쪽 아래**
  - 큰 **점프 버튼**.
  - 그 위에 **상황 행동 버튼**. 근처에 의자나 조교가 있을 때만 나타나고, 아이콘이 바뀐다(🪑/💬).
  - 미로 골에서 로비로 돌아가는 포털은 지금 규칙(design.md 34장)을 따른다. 큐리와 대화창의 "🌀 로비로 돌아가기" 버튼으로만 돌아가고, 행동 버튼으로 바로 순간이동하지 않는다.
  - 그 옆에 **이모지 버튼**. 누르면 6개 이모지가 반원으로 펼쳐진다.
- **아래 가운데**: 채팅 버튼. 누르면 입력창이 키보드 바로 위에 붙는다(지금의 키보드 위 고정 유지).
- **위쪽(손이 덜 닿는 곳)**: 메뉴, 지도, 접속자 수, 소리처럼 가끔 쓰는 것.
- **바닥 톡**: 그 자리로 걸어간다(PC 클릭 이동과 같음).

**정리하는 것 — ⚠️ 예전 발주자 결정을 바꾸는 항목**
- 고정 위치 조이스틱과 1인칭 D-패드(design.md 21장)를 없앤다.
- 1인칭은 일반 3D 게임 관례대로 바꾼다.
  - 조이스틱 앞뒤 = 전진·후진, 좌우 = 옆걸음.
  - 시선은 오른쪽 드래그(PC는 마우스)로만 돌린다.
  - 그래서 "이동하면 시선이 따라 돈다(design.md 20장 시선 동행)"는 없앤다.
- 바꾸는 이유
  - D-패드는 시선 동행과 아날로그 스틱이 부딪혀 시선이 흔들리던 문제를 막으려고 넣은 것이다(21장).
  - 시선 동행을 없애면 흔들림 원인 자체가 사라지므로, 휴대폰에서도 일반 조이스틱을 쓸 수 있다.
- PC의 A/D도 1인칭에서는 옆걸음이 된다(지금은 곡선 선회).

**크기와 접근성**
- 모든 버튼의 터치 영역은 최소 48px, 버튼 사이 간격은 최소 8px.
- 메뉴 → 설정에 아래 옵션을 둔다.
  - 버튼 크기(작게/보통/크게)
  - 왼손잡이 모드(좌우 바꾸기)
  - 시점 감도

## 4. 카메라 **[내 결정]**

- **기본은 3인칭**: 캐릭터 머리 조금 위를 바라보며 부드럽게 따라간다.
- **카메라는 저절로 돌지 않는다.** 이동 방향으로 카메라가 따라 돌면 옆으로 걸을 때 빙글빙글 원을 그리게 된다(21장의 흔들림과 같은 원리).
  - 그래서 카메라는 사용자가 돌린 자리에 그대로 둔다.
  - 대신 **"카메라 뒤로 정렬"**을 둔다: PC는 R, 휴대폰은 오른쪽 화면을 두 번 톡.
- **벽 뒤 당겨오기**: 카메라와 캐릭터 사이에 벽이 있으면 카메라가 벽 앞으로 다가온다(스프링 암).
- **앉기**
  - 교실 의자에 앉으면 스크린이 잘 보이는 각도로 자동 전환한다.
  - 일어서면 원래 시점으로 돌아온다.
- **지도(M)**: 지금의 전체 보기(위에서 내려다보기, 끌어서 이동, 줌)를 유지한다. 내 위치와 방 이름을 표시한다.

## 5. 서버 · 네트워크 변경

- **달리기**
  - 이동 검증 최대 속도를 달리기 속도로 올린다. 기존 `MOVE_SPEED × 경과시간 × 1.5` 규칙에서 기준 속도만 바꾼다.
  - 클라이언트는 걷기/달리기 상태를 따로 보내지 않는다. 원격 캐릭터의 걷기/달리기 동작은 보간 속도로 정한다(지금 방식과 같음).
- **점프**
  - y 좌표는 지금처럼 서버가 0으로 고정한다(나는 핵 방지 유지).
  - 점프는 이모지처럼 **이벤트 방송**으로 보낸다. 받은 화면에서 0.6초 깡총 동작을 보여 준다.
  - 0.6초에 1번으로 제한한다.
- **타자 중 표시**
  - 채팅 입력을 시작하면 "입력 중" 이벤트를 보낸다. 이름표 옆에 "…"를 띄운다.
  - 3초에 1번으로 제한하고, 보내거나 닫으면 끈다.
- **선생님 표시** — ⚠️ 지금 규칙을 바꾸는 항목
  - 지금은 관리자 여부를 서버만 알고 다른 사람에게 보내지 않는다(WorldRoom 주석: 관리자 표시를 상태에 동기화하지 않음).
  - 이름표에 👑 뱃지와 "선생님 항상 표시"를 하려면 `Player` 상태에 `role` 필드(uint8: 0 학생, 1 선생님)를 추가해야 한다.
  - 관리자 코드로 로그인한 사람은 모두 선생님이다. 보조 교사도 포함한다.
  - 값은 서버만 바꿀 수 있다.
- 위 네 가지 모두 대역폭 영향은 무시할 수준이다. 100명 부하 테스트 봇에도 같은 비율로 넣어 다시 잰다.

**동작 클립**
- 달리기·점프 동작은 지금 KayKit 모델에 이미 들어 있는 달리기(Running_A)·점프 계열 클립을 쓴다.
- 새 캐릭터(character-builder 설계)도 이 클립을 포함해 내보낸다. 그 설계 5.1에 반영한다.
- 이 조작 개편은 지금 캐릭터로 먼저 만들고, 새 캐릭터가 오면 같은 클립 이름으로 이어 붙인다.

## 6. 이름표 **[내 결정]**

**모양**
- 둥근 캡슐(흰 바탕, 진한 글씨)이 캐릭터 머리 위에 뜬다.
- 뱃지
  - 선생님(관리자): 색 테두리 + 👑 뱃지
  - AI 조교: "AI" 뱃지
- 내 이름표는 기본으로 숨긴다(설정에서 켤 수 있음).

**크기와 거리**
- 화면에서 보이는 크기가 일정한 범위(예: 글자 12~16px) 안에 머물게 한다. 너무 작아지거나 화면을 덮지 않는다.
- 25m 이상 멀어지면 서서히 사라진다. 지금은 20m에서 갑자기 숨김.

**가려짐**
- 벽 뒤에 있는 사람의 이름표는 반투명으로 흐려진다.
- 가림 검사는 매 프레임 전부 하지 않고, 몇 명씩 나눠 돌린다(성능).

**사람이 많을 때(교실 100명)**
- 이름표를 모두 보여 주지 않는다. 아래 사람만 보여 준다.
  - 화면 안에서 가장 가까운 15명
  - 지금 말하는 사람
  - 선생님
- 이름표끼리 겹치면 위아래로 살짝 비켜 쌓는다.

**말풍선과 같이**
- 말하면 말풍선이 이름표 바로 위에 붙는다.
- 이름표 테두리가 1초간 강조된다.

**설정**: 이름표 보기를 고를 수 있다(모두 / 가까운 사람만 / 끄기).

## 7. 화면 배치(HUD)와 첫 안내 **[내 결정]**

**배치**
- **왼쪽 위**: 지금 있는 공간 이름, 접속자 수
- **오른쪽 위**: 지도, 소리, 메뉴
- **아래 가운데**: 채팅
- **오른쪽 아래(휴대폰)**: 점프, 행동, 이모지
- PC에서는 오른쪽 아래에 이모지·행동 버튼을 작게 둔다. 마우스로도 누를 수 있다.

**첫 안내(코치마크)**
- 처음 입장하면 3단계 안내가 나온다: ① 움직이기 → ② 둘러보기 → ③ 말하기.
- 각 단계는 실제로 해 보면 넘어간다.
- 건너뛰기 버튼이 있고, 메뉴에서 다시 볼 수 있다.

**디자인**
- 버튼·패널은 새 세계관·캐릭터 디자인이 정해지면 그 색과 모양을 따른다.
- 이 문서는 배치와 동작만 정한다.

## 8. 검증

**자동 테스트(순수 함수 단위)**
- 다이내믹 조이스틱의 걷기/달리기 구간
- 왼쪽 가장자리 제외 구역
- 핀치 줌 범위
- 자동 따라 돌기 멈춤 시간
- 이름표 선택 규칙(가까운 15명 + 말하는 사람 + 선생님)
- 선생님 `role` 필드가 관리자 로그인 때만 서버에서 바뀌는지
- 이름표 크기 제한
- 서버 달리기 속도 검증, 점프·입력 중 이벤트 빈도 제한

**E2E**
- PC와 휴대폰 화면 크기(375×812) 각각에서 확인한다: 입장 → 걷기 → 달리기 → 점프 → 앉기 → 채팅 → 이모지.
- 기존 e2e 스크립트 방식(Playwright)을 따른다.

**성능**
- 100명 교실 장면에서 이름표 선택 규칙이 프레임을 떨어뜨리지 않는지 확인한다.
- 100봇 부하 테스트를 다시 잰다.

**발주자 확인**: 실제 휴대폰으로 30초 안에 걷고·둘러보고·말할 수 있는지 본다.

## 9. 진행 순서

1. 조작·카메라: 다이내믹 조이스틱, 핀치, 행동 버튼, E 키, 달리기/점프 + 서버 변경
2. 이름표·말풍선 개편
3. HUD 배치, 설정 메뉴, 첫 안내
4. 검증과 발주자 확인

새 세계관·캐릭터 작업과는 독립적이라 지금 맵에서 먼저 만들 수 있다. 새 캐릭터가 오면 점프·달리기 동작 클립만 연결한다.

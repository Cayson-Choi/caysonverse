# 캐릭터 조립실 (Cayson 토이 피규어) 설계

- 작성일: 2026-10-31
- 상태: 초안 — 발주자 승인 대기 (스타일·참고 대상은 발주자가 "알아서 해"로 위임, 2026-10-31)
- 표기: **[발주자]** = 발주자가 직접 정한 것, **[내 결정]** = 발주자가 "알아서 해"로 위임해 설계자가 정한 것(발주자가 바꿀 수 있음)

## 1. 왜 만드나

지금은 완성된 캐릭터 8종(KayKit 4종 + 왕실 4종) 중 하나를 고르고 색 하나를 입히는 방식이다. 발주자는 학생이 **부품을 골라 조립해서 자기만의 캐릭터를 만드는 것**을 원한다. **[발주자]**

부품 분리 실험(2026-10-31)에서 KayKit 모델은 다음 이유로 이 목적에 맞지 않는다는 것을 확인했다.

- 몸과 옷이 한 덩어리다.
- 머리카락이 캐릭터마다 다른 머리에 붙어 있어서, 다른 얼굴에 씌우면 떠 보인다.

그래서 **블렌더로 공통 몸 하나와 거기에 딱 맞는 부품을 새로 만든다.** **[발주자]**

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**
- 귀여운 3D 피규어. 꼭 레고 모양일 필요는 없다. **[발주자]**
- 부품: 모자 · 얼굴 · 머리카락 · 웃옷 · 바지 · 신발 · 손에 드는 것. 각각 종류와 색을 고른다(손에 드는 것과 왕관 포함). **[발주자]**
- Cayson 로고를 쓴다. **[발주자]** 단, 모자와 옷에는 넣지 않는다. 로고는 나중에 다른 곳에 쓴다(2026-10-31). **[발주자]**
- 어떤 조합이든 부품이 몸에 딱 맞는다. 떠 보이거나 뚫고 나오는 부분이 없다. **[발주자: "공통 몸 하나에 딱 맞게"]**
- 지금 게임의 기능이 그대로 동작한다: 걷기, 앉기(강의실 의자), 말풍선, 이모지, 재접속, 관리자, AI 조교 NPC, 목소리 낭독.

**하지 않을 것 (v1)** **[내 결정]**
- 게임 안에서 옷 갈아입기. 외형은 입장 화면에서만 정한다. 바꾸려면 다시 입장한다.
- 계정이나 서버 저장. 외형은 브라우저(localStorage)에만 기억한다.
- 망토, 왼손 소품, 사용자가 그림을 올리는 기능.
- 소품으로 하는 상호작용. 손에 드는 것은 보이기만 한다.

**실패로 보는 것**
- 기존 장난감이나 게임 캐릭터(레고 미니피규어, 로블록스 등)를 베낀 것처럼 보이는 것.
- 첫 접속 다운로드가 지금(약 18MB)보다 커지는 것.
- 걷기·앉기 같은 동작이 깨지는 것.
- 100명 동시 접속 성능이 지금보다 나빠지는 것.

## 3. 캐릭터 스타일 — "Cayson 토이 피규어" **[내 결정]**

오리지널 디자인이다. 말랑한 비닐 장난감 느낌의 꼬마 피규어로 만든다.

**비율**
- 머리가 키의 약 40~45%인 큰 동그란 머리.
- 짧은 몸통과 짧은 팔다리.
- 손은 손가락 없는 동그란 벙어리장갑 모양. 소품은 손에 쥔 것처럼 손 소켓에 붙는다.

**표면**
- 각진 로우폴리가 아니라 부드럽고 매끈한 면. 서브디비전을 적용하고 폴리곤 수는 아래 성능 목표 안에서 정한다.
- 무광에 가까운 플라스틱 질감, 파스텔 톤 단색.

**얼굴**
- 큰 눈(하이라이트 점 포함), 작은 입, 볼터치를 텍스처로 그린다.
- 피부색을 바꿔도 눈·입 색은 바뀌지 않는다.

**키와 뼈대**
- 키와 뼈 위치는 지금 KayKit Rig_Medium 뼈대와 맞춘다(5장).
- 그래서 의자 높이, 카메라, 충돌 반경, 말풍선 높이를 그대로 쓸 수 있다.

**Cayson 로고**
- 저장소에는 기존 Cayson 로고 파일이 없다. 그래서 새 워드마크를 만든다.
  - 둥근 글꼴의 "Cayson" 글자. 글꼴은 상업·임베딩이 자유로운 OFL 라이선스 글꼴(예: Nunito ExtraBold)을 쓴다.
  - 발주자가 쓰던 로고 파일을 주면 그것으로 바꾼다.
- 들어가는 곳: 입장 화면 조립실 제목.
- 모자·티셔츠 등 캐릭터 부품에는 로고를 넣지 않는다. **[발주자]** 로고 파일은 `art/brand`에 두고 나중에 다른 곳에 쓴다.

- 금속·나무·유리처럼 색이 바뀌면 안 되는 부분(갑옷 금속, 칼날 나무, 헬멧 테두리 등)은 고정 머티리얼로 둔다. 새 텍스처와 반투명 재질은 쓰지 않는다(우주 헬멧은 얼굴 창이 뚫린 모양).
- 투구·우주 헬멧처럼 머리를 감싸는 모자는 어떤 머리 모양과도 뚫림이 없어야 한다.

**롱스커트** **[발주자]**
- 롱스커트는 그대로 두되, 걷기·달리기·점프·앉기에서 다리가 뚫지 않고 자연스럽게 움직여야 한다(2026-10-31).

**팔레트**
- 옷 팔레트 12색에는 금색이 들어간다.

**소품 색**
- 소품은 "색이 바뀌는 부분"과 "고정 부분"으로 나눈다.
- 색이 바뀌는 부분: 책 표지, 깃발 천, 요술봉 별, 풍선, 연필 몸통, 마이크 머리.
- 고정 부분: 책 종이, 깃대, 풍선 끈 등.

**덧붙이는 규칙**
- 목소리(남/여)는 조립실에서 따로 고른다. 지금 캐릭터마다 정해진 목소리를 대신한다.
- 조립실에는 "🎲 랜덤" 버튼을 둔다. 마지막으로 만든 외형은 다음 입장 때 그대로 불러온다.
- 기존 "왕실 4종"은 프리셋 캐릭터 8개로 대체한다. 수업 안내 시간이 8~12분이라 7개 슬롯을 다 고르기엔 짧기 때문이다.
- 프리셋 기준 **[발주자, 2026-10-31]**: 모든 프리셋은 귀여운 아이 얼굴로도 어울리는 동화·모험 주인공이다. 왕·왕비·선생님처럼 어른스러워 보여야 하는 역할은 넣지 않는다. 각 프리셋은 역할에 맞는 모자·웃옷·바지·신발·소품을 모두 갖춘다.
- 프리셋 캐릭터 8개(왕자·공주·마법사·탐험가는 **[발주자]**, 나머지 4개와 차림은 **[내 결정]**):
  - **왕자**: 왕관 + 왕자 옷·파랑 + 흰 긴바지 + 긴 부츠 + 왕홀
  - **공주**: 티아라 + 드레스 상의·분홍 + 롱스커트·분홍 + 구두 + 장미
  - **기사**: 기사 투구 + 기사 갑옷 + 긴바지 + 긴 부츠 + 나무 칼
  - **마법사**: 마법사 모자 + 마법사 로브 + 긴바지 + 마법사 신발 + 마법 지팡이
  - **요정**: 꽃 화관 + 꽃잎 원피스 + 꽃잎 치마 + 샌들 + 요술봉
  - **탐험가**: 탐험 모자 + 탐험 조끼 + 반바지 + 등산화 + 지도
  - **해적**: 해적 모자 + 해적 줄무늬 옷 + 반바지 + 긴 부츠 + 망원경
  - **우주비행사**: 우주 헬멧 + 우주복 + 우주복 바지 + 우주 부츠 + 깃발
- 프리셋은 부품 조합일 뿐이다. 서버로는 일반 외형 필드로 전송되고, 누른 뒤 자유롭게 바꿀 수 있다.
- 망토는 v1에서 넣지 않는다.

## 5. 기술 방식

### 5.1 3D 자산 (블렌더)

**뼈대와 애니메이션 재사용** **[내 결정]**
- 새 몸과 부품은 지금 쓰는 **KayKit Rig_Medium 뼈대(CC0)**에 맞춰 만들고 가중치를 준다.
- 쓰는 동작 클립은 기존 GLB에서 그대로 가져온다.
  - 지금 쓰는 것(`CLIP`): Idle, Walking_A, Sit_Chair_Down, Sit_Chair_Idle, Sit_Chair_StandUp
  - 조작 개편 설계(2026-10-31-controls-ux-design.md)에서 쓰는 것: 달리기 Running_A, 점프 Jump_Full_Short
  - 롱스커트 전용(다리 움직임을 줄인 파생 클립): Walking_A_LongSkirt, Running_A_LongSkirt, Jump_Full_Short_LongSkirt. manifest `clipVariants`로 롱스커트를 입었을 때만 쓴다(2026-11-01).
  - 짧은 치마 전용(보폭은 그대로, 무릎 뒤로 접힘만 제한해 발꿈치가 뒷단을 지나가지 않게): Walking_A_ShortSkirt, Running_A_ShortSkirt, Jump_Full_Short_ShortSkirt. 치마·꽃잎 치마에 쓴다(2026-11-01. 롱스커트 동작을 쓰면 다리가 보여 뒷걸음질처럼 보였다).
- 그 밖의 클립은 넣지 않는다.

**교체식 구조**
- 겹쳐 입히지 않는다. 몸을 구역으로 나누고, 각 슬롯은 자기 구역을 **덮는 메시 하나로 교체**한다.
  - 웃옷 = 몸통 + 윗팔
  - 바지 = 엉덩이 + 다리
  - 신발 = 발
- 머리와 손은 항상 피부 메시다. 그래서 어떤 조합에서도 뚫고 나오는 부분이 생기지 않는다.

**머리카락과 모자**
- 머리카락은 머리 뼈에 붙는 메시다.
- 모자를 쓰면 머리카락이 모자를 뚫지 않아야 한다. 방법(머리카락의 "모자용 변형" 메시를 둘지, 모자를 모든 머리 모양보다 크게 만들지)은 빌더가 정한다.
- 단, 6장의 렌더 점검을 통과해야 한다.

**파일 구성**
- 하나의 GLB `character.glb`에 넣는다: 뼈대, 모든 부품 메시(이름 규칙 `slot__id`, 예: `hair__ponytail`), 동작 클립 13개(기본 7개 Idle, Walking_A, Running_A, Jump_Full_Short, Sit_Chair_Down, Sit_Chair_Idle, Sit_Chair_StandUp + 롱스커트 변형 3개 + 짧은 치마 변형 3개).
- 함께 `character.manifest.json`을 내보낸다. 슬롯별 부품 id, 한글 이름, 색 적용 여부를 담는다.

**색 적용 방식**
- 부품 기본색은 흰색/회색 텍스처이고, 머티리얼 색으로 곱한다.
- 얼굴 무늬처럼 색이 바뀌면 안 되는 부분은 별도 머티리얼로 둔다.

### 5.2 네트워크 · 서버

`Player` 스키마의 `character`·`tint`를 아래 uint8 필드로 바꾼다. 모두 입장 때 한 번만 보내므로 대역폭 영향은 없다.

`hat, hatColor, hair, hairColor, face, skin, top, topColor, bottom, bottomColor, shoes, shoesColor, item, itemColor, voice`

- `JoinOptions`와 서버 `validateJoinOptions`가 각 필드를 범위로 검사한다. 범위 수는 `shared/constants.ts`의 단일 소스에서 가져온다.
- 잘못된 값이 오면 입장을 거부한다(지금 규칙과 같다).
- 재접속 캐시(`identityCache`)와 입장 화면 저장값도 이 구조로 바꾼다.
- 예전 형식으로 저장된 값은 기본 외형으로 대체한다.

### 5.3 클라이언트

**모델 불러오기와 조립**
- `character.glb`를 한 번만 불러온다.
- 아바타마다 `SkeletonUtils.clone`으로 복제한 뒤 선택한 부품만 보이게 하고 색을 입힌다.
- 지금 `cloneTinted` 자리를 대신한다.
- 숨긴 부품은 그리지 않는다. 예: `visible=false` 또는 메시 제거.

**그대로 유지하는 것**
- 원격 보간, 애니메이션 스로틀, 말풍선, 이모지, 닉네임표.

**입장 화면**
- 지금 "캐릭터 8종 버튼 + 색 8개"를 **조립실**로 바꾼다.
- 조립실 구성: 돌려 볼 수 있는 3D 미리보기, 슬롯별 종류 칩, 색 견본, 프리셋 캐릭터 8개, 랜덤 버튼, 목소리 선택.
- 모바일 화면에서도 쓸 수 있어야 한다.
- 새 배치(Task 7b, 2026-11-01): 밝은 하늘 정원 그림(화면마다 한 장, AVIF 먼저)의 받침대 위에 인형이 서고, 발은 받침대 윗면 가운데에 맞춘다. 학교 이름·장식은 넣지 않는다(모든 체험이 같이 쓰는 입구).
  - 넓은 화면: 위쪽 바(Cayson 배지 + 제목 / 관리자 알약), 왼쪽 유리 패널(추천 캐릭터 그림 카드 + 🎲, 목소리), 오른쪽 유리 패널(아이콘 탭 레일, 부품 그림 카드, 색), 가운데 무대 아래 ⟲ 이름판 ⟳와 큰 입장 버튼.
  - 휴대폰: 위쪽 무대 + 아래 시트(높이 47% ↔ 88%, 안에서 스크롤, 입장 버튼은 시트 아래 고정). 태블릿 세로·가로 휴대폰은 시트가 오른쪽 패널이 된다.
  - 부품·프리셋 카드 그림은 미리보기 렌더러로 실행 중에 그린다(지금 색, 프레임당 2장). 제목용 글꼴은 Jua(OFL) 부분집합을 직접 보낸다.

### 5.4 성능 · 용량 목표

- `character.glb` 단독: **4.5MB 이하**(지금 캐릭터 GLB 합계 약 14.7MB). 처음엔 3MB였으나 프리셋 차림 부품 25개를 넣으며 올렸다(2026-10-31). 첫 접속 8MB 목표는 그대로다.
- 첫 접속 전체 다운로드: **8MB 이하**(지금 약 18MB).
- 아바타 1명당 그리는 메시: 8개 이하(지금과 비슷한 수준).
- 100명이 있는 강의실 장면에서 중급 모바일 30fps 목표를 유지한다(기존 설계 6장).

## 6. 검증

**자동 테스트**
- 외형 필드 범위 검증.
- 직렬화와 재접속 캐시.
- manifest와 GLB 메시 이름 일치 검사: 모든 부품 id가 실제 메시로 존재해야 한다.
- 기존 서버·클라이언트 테스트 갱신.

**렌더 점검**
- 슬롯별 모든 종류가 최소 한 번씩 나오는 조합 묶음을 헤드리스로 렌더한다. 여기에 랜덤 조합 30개 이상을 더한다.
- 서 있기, 걷기, 앉기 자세로 찍어 뚫림·떠 보임이 없는지 확인한다.

**부하 테스트**
- 100봇 부하 테스트에서 봇이 랜덤 외형으로 입장하게 하고 30분 측정한다(서버 게이트는 기존과 같다).

**발주자 확인**
- 7장의 1단계(스타일 시안)와 4단계(최종)에서 발주자가 직접 본다.

## 7. 진행 순서 (발주자 확인 지점 포함)

1. **스타일 시안**
   - 블렌더로 공통 몸을 만든다.
   - 머리카락 2종, 웃옷·바지·신발·모자 각 1종을 만들어 렌더 이미지와 웹 미리보기로 보여 준다.

## 9. 위험
